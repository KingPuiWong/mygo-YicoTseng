# 端到端验证边界与故障清单

正式实现的唯一测试入口为 `npm run e2e`。它从插件公开接口开始，访问实际配置的音源，获取真实曲库与歌词、下载真实音频并用 FFmpeg 解码；同时经过收藏、最近播放、重新加载插件与持久存储。没有单元测试、网络 mock 或虚构曲库。

脚本中的 host 适配器仅提供 MyGo 的翻译、持久存储接口，因此它验证的是插件协议到真实音频解码的完整链路，不代表已完成原生 MyGo 窗口、音频设备或其 JavaScript 引擎的验证。原生应用的验证需单独记录，不能用脚本结果代替。

## 编码前列出的失败方式

- 曲库接口超时、非 200、接口变更或返回空数据。
- 只取第一页而漏歌；分页重复或把其他歌手同名歌曲混入曲库。
- 曲源字段或目录结构不同，导致标题、封面、时长或专辑归属丢失。
- 曲库缓存过期后刷新失败，错误地覆盖原有可用缓存。
- 搜索、专辑页、收藏或最近播放引用了不在曲库中的 ID。
- 收藏或最近播放只保存在内存，重启后丢失；取消收藏未生效。
- 播放接口因会员、付费、地区或版权限制不返回地址，或仅返回试听片段。
- 播放链接过期、音频请求失败、下载内容不是音频或宿主不支持其格式。
- 中英文名字和译文不一致；同一歌曲的歌词不匹配或没有时间轴。
- Node 可以运行但 MyGo 所用引擎不支持某个 API；原生应用没有发现插件或未切换音源。

不为推测性的竞态或安全边界加入额外机制。第一版只处理上述可复现的正常错误路径。

## 可重复工件

每次运行在 `artifacts/e2e/<时间>/` 输出 report.json、catalog.json、journey.json、音频样本、ffprobe.json 和 FFmpeg 解码日志。报告记录插件源码 SHA-256 与数据来源。运行工件忽略提交；仓库另存一份去除临时播放地址与歌词正文的验证摘要。

## 0.2.0 编码前补充的失败方式

- 播放设置请求高品质，插件仍固定取 128 kbps；或上游只给低码率，却被错误标成 320 kbps、无损。
- 官方投稿已删除、限制访问、没有可用音轨，或返回不属于曾轶可本人账号的资料。
- 临时音频地址过期、缺少请求头，或者音频格式与 MyGo 支持范围不符。
- 现场、串烧、录音室重录和原专辑版本混为一谈，搜索结果或收藏自动替换原版本。
- 给现场或重录套用原版歌词，时间轴不匹配。
- 新版缓存或 ID 变更导致旧收藏与最近播放丢失。
- 一个曲源暂时失联，连另一个曲源已知的歌曲也不能浏览。

端到端旅程必须包含：原曲目 ID 与版本保留、高品质《夜车》真实下载并验证码率、官方现场和重录的单独入口与标签、两种来源的收藏落盘恢复，以及官方音轨完整下载/解码。完整官方曲库审核使用 `E2E_ALL_OFFICIAL=1 npm run e2e`，逐条访问真实投稿与音轨；不使用单元测试和网络 mock。
